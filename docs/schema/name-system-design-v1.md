## 1. 要解决什么

多源（竞彩、训练源、五美元盘口、BSD、雷速截图、旧足球分析仓库等）队名／赛事名写法不一。痛点是：局部改当天几场会复发；缺「新名自动归组＋雷速／旧仓升格」闭环；若比赛行冗余存队名并以全文搜改当同步，映射表改了也不会全站变。

本方案把名称组、常用名、别名、待确认星号、升格来源、待定池、映射表、身份编号收成一套可执行系统：改映射表一次，全库读路径生效。

## 2. 目标与非目标

### 2.1 目标

1. **一组一实体**：一组＝同一队或同一赛事的全部名称；常用名对多别名；新名先搜索再匹配——能并入加别名，对不上新建组并默认显示＋标星。
2. **有人工智能参与的自动化**：新名入库走搜索／检查／归组／写映射；雷速截图到达则升格对应仍标星实体；无雷速可用旧仓高置信升格；遵守升格优先级，禁止猜挂。
3. **架构目标态：编号＋映射表**：比赛／赛程行只存 `team_id`／`league_id`；显示名与星号实时引用映射表。历史冗余文本可迁移期并存，验收不以扫改文本列为准。
4. **点名某天＝全库同实体同步**（同步含义见第 3.10 节）。
5. **假星可验收归零**：已升格不标星；真待审可标星。
6. **大陆站与正式库一致**：名称包同步推送，推后冒烟。

### 2.2 非目标

1. 不规定赔率、赛果、预期进球等业务算法；这些入口只须接入名称入库闸。
2. 不立刻删除历史比赛文本列；但不把扫改文本列当目标态。
3. 不把 BSD／竞彩／五美元原文升格为常用名。
4. 不自动合并男女队、一线队与青年队。
5. 有身份编号 ≠ 已升格；编号不单独加减星。
6. 外部取证可由人工智能起草，歧义或无出处时停在待定池，不强制全自动升格。

## 3. 术语

### 3.1 名称组

同一赛事或同一队伍的全部名称，对应一个身份编号（队 `team_id`，赛事 `league_id`）。组内含零个或一个已升格常用名、若干别名、无常用名时的默认显示名。

### 3.2 常用名

用户熟悉、页面优先展示、且已升格的中文名。只来自允许的升格来源（第 5 章），不得由 BSD 等外源自动升格。

### 3.3 别名

组内除常用名外的写法。用于对场、归组、搜索与无常用名时的默认显示候选；**不能**凭别名消星或升格。

### 3.4 默认显示

尚未升格时，从组内选的一条非空写法供页面显示并继续标星。顺序：非空来源文本 → 实体上其他非空名 → 别名（优先含汉字，再按写入顺序）。组内有任一非空名则不得留空；全空仍标星（原因码 `name_absent`）。

### 3.5 待确认星号

前端 `*`，表示尚未落到熟悉常用名。接口待确认布尔为真则标星。已升格不标星；临时名／待定／仅默认显示／名称为空必须标星。

### 3.6 升格来源

| 取值 | 含义 |
|---|---|
| `leisutiyu`／`雷速体育`（及 `leisu`、`雷速`） | 雷速确认，首选 |
| `legacy_high_confidence` | 旧足球分析仓库高置信 |
| `human_finalize` | 人工定稿 |
| `user_correct` | 用户改正 |
| `temporary` | 临时名，不算升格，继续标星 |

`established` 仅兼容历史同义；新写入优先用上表明确来源。空白升格标记仅兼容名称包历史种子；正式库 `name_zh_canonical` 有字本身不是升格证明。

### 3.7 待定池

无法安全并组或升格时存放原文、线索与拒绝原因。歧义、弱模糊无上下文、男女／青年队边界不清、禁止猜挂的情形一律进池并标星。

### 3.8 映射表

以身份编号为键的表集合（至少 `teams`、`team_aliases`、`leagues`、`league_aliases`，及待定／审计表）。**显示名与星号的唯一权威来源。** `api/resources/name-standard/` 名称包是种子与发布物，须与正式库语义一致。

### 3.9 身份编号

名称组主键（`team_id`／`league_id`）。目标态比赛行只存编号；编号本身不加减星。

### 3.10 「同步」（全文固定）

- **允许**：改映射表（及名称包）中该实体的常用名、升格来源、待确认、别名，使所有引用该编号的读路径立刻变；并把该状态推到大陆站并冒烟。
- **禁止当常态**：全文搜索替换比赛／赛程文本列来「修显示」。

后文凡写同步，均指此义，不再另述。

## 4. 数据模型目标态

### 4.1 比赛行与读路径

1. 赛程行存 `home_team_id`、`away_team_id`、`league_id`（或等价字段）。
2. 构造比赛对象时按编号读映射表，推导显示名与 `*_pending_confirm`。
3. 冗余队名／赛事名文本不得当常用名权威。

### 4.2 映射表最低字段

- 球队：`id`、`name_zh_canonical`、`promotion_source`／`promotion`；别名表含 `team_id`、`alias`、`source`（待确认类可以 `_pending_confirm` 结尾）。
- 赛事与赛事别名字段对称。
- 待定池能记原文、规范化键、来源、线索、拒绝原因、状态。

### 4.3 升格与星号如何读

1. `pending_confirm=true`（或别名待确认后缀）→ 未升格，标星。
2. 升格来源命中第 3.6 节允许集合 → 该规范名为常用名，不标星。
3. 规范名列有字但无合法升格来源 → 不得仅凭「有字」消星（名称包已升格集合中的历史兼容除外）。
4. 同文字别名不能把未升格规范名消星。

### 4.4 显示推导顺序（前后端共用；前端不另写规则）

1. 有编号且已升格 → 显示常用名，不标星。
2. 有编号未升格 → 默认显示，标星。
3. 无编号 → 能解析则只填空槽编号；解不出进待定池，标星。
4. 来源文本已是某条已升格常用名 → 可不标星，并尽快回填编号。
5. 别名只用于补显示或悬停，不进入消星判断。

嵌套与扁平字段须同一推导结果；历史原文列不得优先于常用名／默认显示。

### 4.5 历史冗余文本

迁移期可保留原文列作审计与回填线索。回填脚本只填空槽、默认不建实体。修正名称只改映射表；旧常用名降为别名。验收拆开「空编号归零」与「页面常用名优先」。

## 5. 升格优先级与星号

### 5.1 优先级（高→低）

1. 雷速体育  
2. 旧仓高置信（仅当尚无雷速，且能高置信对照同一实体）  
3. 无雷速且无旧仓高置信 → **不升格**，默认显示＋标星；歧义进待定池  
4. 人工定稿／用户改正：随时可写，用于补齐或纠正  

BSD 等外源、竞彩／五美元原文：只作别名。

### 5.2 星号表

| 状态 | 星号 |
|---|---|
| 已升格（雷速／旧仓高置信／人工／用户改正） | 不显示 |
| 临时名／未升格／待定开放／名册无此名 | 必须显示 |
| 来源名与规范名都空 | 必须显示（`name_absent`） |

补充：相近名各自判断（如切尔西已升格，切尔西女／青年队不因此消星）；名册缺失时记警告，禁止全员标待确认。

## 6. 新名称入库闸（七步）

新名按序处理；前面足够确信则停止落库。细则见 `v2_0-name-resolve-group-rules.md`。

| 步骤 | 名称 | 自动化边界 |
|---|---|---|
| 1 | 规范化 | **全自动。** 去空格、全半角、空白归一、拉丁不区分大小写。后缀（FC 等）只作弱线索。保留原文；规范化键与现有 `norm`／`norm_key` 一致。 |
| 2 | 精确命中 | **全自动。** 别名／常用名／来源名不区分大小写全等。唯一命中则只加别名；多实体→歧义进第 6 步。 |
| 3 | 同场多证据（队） | **有条件自动。** 另一侧已映射、时间窗内（常用前后十五分钟）、比分一致或窗内唯一，且对手／时间／比分至少两项一致。比分不得单独定身份。 |
| 4 | 赛事侧 | **有条件自动。** 主客已映射且本场 `league_id` 已定，新名是赛事字符串时可并入。仅「长得像」不够。 |
| 5 | 外部取证 | **人工智能起草＋可复查；无把握不自动升格／并组。** 核对官方名、维基、雷速、U23／女足是否独立实体。无出处禁止静默合并。 |
| 6 | 歧义闸 | **全自动拦截。** 多候选、弱模糊无上下文、国家队简称冲突、同城多队、性别／年龄／二队标记不一致 → 进待定池并标星。 |
| 7 | 落库 | **执行已通过闸的动作；升格另走第 5／7／8 章。** 并入只加别名；新建组＝默认显示＋待确认；待定只记线索。 |

**闸内禁止**：猜挂；男女／青年队自动合并；外源升格；弱相似单独定组；为 BSD／预期进球硬挂；`create=True` 冒充已升格；跳过待定池消星。

## 7. 雷速升格管线

1. **输入**：截图或结构化名单；上下文（开赛、主客、比分、赛事）看不清不用。  
2. **匹配**：约定窗口内比分或开赛对得上才定同一场；解析／回填编号；对不上或歧义不升格。  
3. **动作（只改映射表）**：`name_zh_canonical`＝雷速写法；升格来源＝雷速；待确认＝假；旧名保留为别名。全库同实体随之变。  
4. **未覆盖实体**：走第 8 章或保持标星。  
5. **发布**：进正式库与名称包 → 推大陆站 → 冒烟；保留审计（输入、编号、旧新名、跳过原因、回滚）。

---

## 8. 旧仓高置信升格管线

**条件**：尚无雷速常用名；旧仓能高置信对上同一实体。  
**动作**：映射表写旧仓常用名＋`legacy_high_confidence`、消星；旧临时名作别名。  
**不得升格**：多候选冲突、仅弱相似、男女／青年边界、已有雷速（除非用户改正）、旧仓也不高置信。  
名称包中历史高置信行记 `legacy_high_confidence`；雷速确认后改为 `leisutiyu`。

## 9. 组件分工

| 组件 | 职责 |
|---|---|
| 共享技能 | 名称类任务强制入口；触发取证、干跑／应用脚本、审计；禁止绕闸改库、禁止未改映射表却称已全库同步 |
| 仓库／接口 | 读路径按编号引用映射表；待确认与待定池逻辑；所有新字符串入口过闸；升格脚本只改映射表与名称包；前端不实现第二套规则 |
| 例程 | 新名观察、待定提醒、雷速干跑、推送后冒烟；成功标准写清改了哪些编号、是否推送、冒烟结果 |
| 分析师 | 歧义与取证未定项；用户点名某日错误 → 改映射表 → 推大陆站冒烟；维护回滚说明 |
| 后端 | 编号完整率；读写路径唯一；名称包与库一致；不提供「按日改比赛文本冒充对齐」的正式接口 |

---

## 10. 大陆站与防复发

1. 发布物同时含正式库映射状态与名称包；禁止库／包长期分叉。  
2. 推送后冒烟：抽检已升格不标星且显示常用名；未升格仍标星；名册缺失不得全员待确认。失败＝发布失败，回滚或热修。  
3. 禁止只改本地／只改前端／只改某日文本却向用户宣称已修好。

## 11. 验收清单

汇报须拆开「空编号归零」与「页面常用名优先」。

### 11.1 空编号（E）

- [ ] **E1** 约定窗口空槽：可解析已填；解不出进待定且标星。  
- [ ] **E2** 回填只填空槽；默认不创建；不为过验收新建并标已升格。  
- [ ] **E3** 有编号仍可无常用名、仍可标星；空编号归零 ≠ 常用名已对齐。

### 11.2 页面常用名优先（D）

- [ ] **D1–D2** 赛程与数据表同一套：有常用名走规范名路径，不因有编号就只显示原文。  
- [ ] **D3** 星号只跟接口待确认布尔。  
- [ ] **D4** 反例为零：有编号且常用名非空，页面却仍只显示抓取原文 → 失败。

### 11.3 升格与假星（S）

- [ ] **S1** 合法升格常用名不标星。  
- [ ] **S2** 真待审（无雷速且无旧仓高置信／歧义／待定／空名）必须标星。  
- [ ] **S3** BSD 等外源未导致升格。  
- [ ] **S4** 无男女／青年队自动合并。

### 11.4 雷速／旧仓（L）与入库闸（G）

- [ ] **L1** 雷速批次：匹配实体映射表已写雷速来源并全库消星。  
- [ ] **L2** 无雷速有旧仓高置信：次选升格或显式待审，无猜挂。  
- [ ] **L3** 每条升格可审计、可回滚。  
- [ ] **G1** 新名：并入只加别名；对不上新建组并标星。  
- [ ] **G2** 第 5 步无出处静默合并次数为零。  
- [ ] **G3** 点名某日错误后改映射表，其他日期同编号一并正确。

### 11.5 大陆站（C）与方向样例

- [ ] **C1–C3** 包与库一致；推后冒烟通过；无「只改本地未推送」的已宣称修复。  
- [ ] 利雅得新月／坎布尔为常用名；利雅得希拉尔／金堡尔为别名（用对照表脚本，不手工翻仓）。

## 12. 分阶段落地

| 阶段 | 内容 | 门禁 |
|---|---|---|
| A 文档定稿 | 本文＋细则一致＋技能入口 | 术语、同步含义、优先级、禁止清单无歧义 |
| B 清假星 | 能升格走管线；不能则恢复标星；回填空编号 | 假星归零；E／D／S 分项过 |
| C 入库闸 | 全入口接七步；补同场／赛事侧缺口；取证可复查 | G 组过；新建不冒充已升格 |
| D 雷速／旧仓管线 | 输入、匹配、升格、审计、推送冒烟脚本化 | L＋C 过 |
| E 技能强制入口 | 名称任务先过技能／本文；点名升级为映射表全库修复 | 连续两批雷速＋一批旧仓无假星复发 |

不得跳过前一阶段门禁。

## 13. 禁止清单

1. 靠用户反复点名局部修星／常用名当常态；同一实体应改映射表一次全库生效。  
2. 把同步做成全文替换比赛文本列。  
3. 目标态依赖冗余队名文本当显示权威。  
4. 无雷速且无旧仓高置信时自动升格。  
5. 猜挂（含为 BSD、预期进球、过验收）。  
6. 外源升格为常用名。  
7. 男女队、一线队与青年队自动合并。  
8. 无同场上下文时用弱模糊自动并组。  
9. 身份编号单独加减星；有编号＝已升格。  
10. 名册缺失时全员标待确认。  
11. `create=True` 静默建成已升格。  
12. 只改本地／前端／某日文本不推送冒烟却宣称已修好。  
13. 空编号归零与页面常用名优先混报。  
14. 别名单独消星；未升格规范名仅因「列里有字」消星。  
15. 入库闸第 5 步无出处静默合并。  
16. 用旧仓覆盖已有雷速常用名（除非用户改正）。  
17. 跳过阶段门禁上线自动升格却不清假星债。
