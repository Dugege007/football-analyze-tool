# 新名称并组与新建组规则（v2.0）

> 用户 2026-10-19 在分析师私聊定稿。以后改规则，只在本文基础上优化，不另起一套。
> 常用名来源、升格标记与前端星号的产品规则见同目录 `v2_0-name-canonical-and-star-rules.md`。
> 2026-10-20：七步的自动化边界、同步含义与禁止清单以同目录 `name-system-design-v1.md` 第 6 章和第 13 章为准。本文步骤正文不另写一套。
> 待定池表结构与自动映射实现草案见 `alias_pool.sql` 与 `api/app/alias_pool.py`。七步入口是 `api/app/name_resolve_gate.py`。

## 目标

把未知字符串挂到「同一支球队」或「同一项赛事」那一组上。对不上就新建一组。男子与女子、一线队与青年队（含预备队、年龄段梯队）默认不自动合并。

一组等于一个实体编号：球队是 `team_id`，赛事是 `league_id`。别名挂在实体上。常用名（`name_zh_canonical` 且已升格）只决定页面优先显示哪一句；对场钥匙靠别名表与同场上下文，不靠「常用名表里有没有 BSD 行」。

## 输入

- 新名原文（可带来源：BSD、竞彩、五美元盘口、雷速体育等）。
- 可选上下文：开赛时间、主客、比分、赛事名、对手名、赛季或轮次。

比分与赛果只能用来拒绝错误对场，或作为「同场多证据」里与时间、对手并列的一项；不得单独当作「确认队名身份」的唯一证据，也不得写入待定池出现记录的赛前上下文。

## 步骤（按顺序，前面足够确信就停）

### 1. 规范化

去掉首尾空格，统一全角与半角，把连续空白收成一个空格，拉丁字母不区分大小写。常见俱乐部后缀（例如 FC、CF）只作弱线索，不得单靠后缀折叠定组。保留原文写入别名或待定池，不用规范化结果当唯一业务键。

规范化键应与 `api/app/team_pending.py` 的 `norm`（及待定池 `norm_key`）保持一致。

### 2. 精确命中

在 `team_aliases` 或 `league_aliases`、实体常用名、来源名里做不区分大小写的全等。命中唯一实体则并入该组，置信度高。同一规范化键指向多个实体时，视为歧义，进入第 6 步，不得猜挂。

### 3. 同场多证据（队名专用，最强）

若有一场比赛上下文：另一侧已经映射、开赛时间在约定窗口内（当前实现常用前后十五分钟）、比分一致，或时间窗内比分唯一，则可以把新名并入该侧队组。单侧对上不够时，要求对手、时间、比分至少两项一致。证据不足时不得为了对上 BSD 场次或预期进球而硬挂。

### 4. 赛事侧

主客两边都已映射，且本库该场 `league_id` 已定，而新名是赛事字符串时，优先并入该 `league_id` 组。仅「名字长得像」不够。

### 5. 外部取证

上网或权威站核对：官方中英文名、维基百科、雷速体育、同一杯赛树下 U23 或女足是否独立实体。能明确指向库内已有实体则并入；明确是新实体或库里没有则新建组（见第 7 步）。外部取证的结论要可复查，禁止无出处的静默合并。

### 6. 歧义闸

下列任一出现则不并入、不硬猜，进待定池并标星：

- 多名候选实体（例如切尔西与切尔西女）。
- 只有弱模糊匹配（编辑距离、缩写、前后缀剥离、子串包含）且没有同场上下文。
- 国家队简称冲突、同城多队、青年队或预备队边界不清。
- 名称含性别、年龄段、二队等歧义标记，与候选实体标记不一致。

### 7. 落库

- **并入**：在对应别名表增加一行，`source` 写清平台与批次；不改常用名，除非雷速体育确认或人工明确定稿升格。
- **新建组**：建立实体或待定池记录；默认显示名等于该新名（或组内已选定的代表写法），`pending_confirm` 为真（或等价的待确认星号布尔为真），直到升格。
- **待定**：只记原文、线索与拒绝原因，等待人工或后续证据；禁止为补全 `bsd_event_map` 或预期进球而猜挂。

## 无常用名时的默认显示

一组表示同一个赛事或同一支球队的全部名称。若尚未设置常用名（未升格），则在组内选定一个写法作为默认显示，并继续标星。选定规则当前约定为：优先已有非空的 `name_zh_canonical`（即便仍是临时名）；否则用该组最早稳定出现、或本次新建时的原文。升格为常用名之后取消星号。身份编号有无，不单独加减星。

## 成功与失败标准

- 成功：新名能稳定指向唯一的 `team_id` 或 `league_id`，或明确建成新组。
- 失败：多候选或证据不足则待定；禁止为了对上 BSD 或预期进球而猜挂。

## 刻意不做

- 不用 BSD 写法升格常用名。
- 不用「长得像」单独定组。
- 不自动合并男女队、一线队与青年队。

## 与星号、常用名文档的关系

升格来源优先级、名册缺失时不得全员标星、赛程与数据表字段路径，仍以 `v2_0-name-canonical-and-star-rules.md` 为准。本文只管「新名如何进组或新建组」，以及「无常用名时组内默认显示并标星」。

## 实现状态

本节记录代码与上文步骤的对照。步骤正文不因本节改写。2026-10-20 起，自动化边界以 `name_resolve_gate.py` 为准，并接入竞彩场次构建、赛果入库和 BSD 未解析路径。这些入口优先观察进待定池，不把新字符串写成已升格常用名。

1. 规范化已经实现。`api/app/team_pending.py` 的 `norm` 与 `api/app/alias_pool.py` 的 `norm_key` 一致。宽松键只删除空白和方案点名的标点，不靠 FC、CF 一类后缀折叠定组。
2. 精确命中已经实现。规范化键与别名或常用名全等，且只指向一个实体时，待定池写入别名并回填空着的身份编号，不改常用名。
3. 同场多证据由入库闸执行。另一侧已经映射、开赛时间在前后十五分钟内，并且对手与时间至少构成两项证据时，可以把新名并入该侧已经填写的球队编号，只加别名。比分可以拒绝错误对场，或作为第三项证据；比分单独不够。前后缀、编辑距离和子串包含即使带了同场上下文，仍然只作候选，不自动并组。该侧编号还空着时，不得为了对上 BSD 或预期进球而新建球队。
4. 赛事侧由入库闸执行正向动作。主客编号都已映射，且本场 `league_id` 已定时，新的赛事字符串并入该赛事组，只加别名。仅「名字长得像」仍然不够。球队已有赛事与本次没有交集时，宽松键候选不自动并组。
5. 外部取证不抓取网页、维基百科或雷速体育。证据不足、又带有开赛或对手等线索时，闸把 `needs_external_evidence` 和线索写入待定池。人工智能或人工稍后填写。无出处不得静默合并，也不得升格。
6. 歧义闸收成 `alias_pool.detect_ambiguity` 一道。性别、年龄段、二队和已经点名的同名实体，以及候选与目标的标记不一致时，都不并入。编辑距离、缩写和子串包含没有自动并组。只有弱模糊、又没有同场上下文时，不得并组。
7. 落库分三条。并入已有组时只写别名，不改常用名，除非另走雷速或旧仓高置信升格脚本。新建组走 `resolve_or_create_team` 与 `resolve_or_create_league`：默认显示等于这条新名；名册里尚未升格时 `pending_confirm` 为真。该列不在正式表结构里时不改表，别名 `source` 以 `_pending_confirm` 结尾，星号同样为真。这次新建不得写成雷速体育、人工定稿或旧仓库高置信升格。名册里已经升格的写法建组时不把星号重新打开。BSD 来源的 `create=True` 直接拒绝，不新建实体。待定池本身仍不新建球队或赛事。

无常用名时的显示已经接在读路径上。赛程与数据表在常用名为空时，按来源文本、实体上另存的名称、含汉字优先的别名挑一条非空显示，并保持 `*_pending_confirm` 为真。别名不参与把星号消掉。上文「优先已有非空 `name_zh_canonical`，否则用最早稳定出现或本次原文」仍是产品约定；临时常用名继续显示其文字并标星。
