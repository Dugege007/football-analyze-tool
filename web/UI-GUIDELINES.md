# 网页界面规范

## 规则一：注释性说明不直接写在页面上（用户 2026-10-10 确定，2026-10-18 收紧提示内容）

- 注释性说明不直接写在页面正文里。页面正文包括列标题中的括号注释、表单项下方的解释、卡片里的长段说明，以及图例和状态栏里的规则解释。
- 栏目、标签或列标题如果需要提示，在文字旁边放一个小问号。鼠标移到问号上时出现悬停提示（Tooltip）。悬停提示只写数据来源，或者只写如何使用当前界面。规则解释和口径说明不进入悬停提示。内容边界见规则二。
- 统一使用组件 `web/src/components/HelpTip.tsx`：
  - `<HelpTip tip="说明文字" />`：单独的小问号，放在标题或标签文字后面。`tip` 只写数据来源或如何使用。
  - `<LabelWithHelp label="标签" tip="说明文字" />`：标签文字加小问号，可以直接用作表格列标题、卡片标题、表单项标签。`tip` 只写数据来源或如何使用。
  - 说明文字里可以用换行符分段。
- AG Grid 数据表的列标题使用 AG Grid 自带的 `headerTooltip`（悬停列标题时显示的提示），不在列标题里写括号注释。`headerTooltip` 与问号提示适用同一条内容限制：只写数据来源或如何使用。
- 下列内容不算注释，照常直接显示：空状态提示（例如「这一天正式库里还没有比赛数据。」）、错误和加载失败提示、操作结果提示、按钮文字、数据本身、状态标记（例如「有截断」标签）。这些直接显示的文字仍然不得写入程序逻辑或内部规则，见规则二。
- 表格单元格里没有数据时显示「-」。旁边的小问号只说明数据来源，或说明读者下一步如何查看。

## 规则二：页面和提示里不写程序逻辑与内部规则（用户 2026-10-18 确定，硬规则）

程序逻辑和内部规则不得出现在页面上，也不得出现在问号提示、帮助提示或列标题悬停提示里。问号提示指 `HelpTip` 和 `LabelWithHelp` 使用的 Tooltip。帮助提示与问号提示是同一类悬停说明。列标题悬停提示指 AG Grid 的 `headerTooltip`。

前端读者能看见的说明只允许下面两类，并且用完整句子写清楚：

1. 数据来源。说明这一项数据从哪里来，例如哪一个接口、哪一个采集来源、是否手工录入、数据截至什么时间。
2. 如何使用。说明读者怎样操作当前界面，例如点哪里、开关打开后页面多显示什么、复制出去的文本包含什么。

业务口径、计算口径、回退顺序、缺数据时程序如何处理、阈值如何判定，只写在文档里。文档包括本规范的留档、`docs/schema/` 下的口径文档，以及代码注释。页面和提示不承担代码注释的职责，也不存放内部实现规则。

禁止出现在页面或提示里的例子：多家平均的提示写成「盘口或抓取时刻缺失的格子不计算预警。」这句话解释的是缺数据时程序不计算预警，属于内部处理逻辑。

允许出现在提示里的例子：

- 「数据来源：手工底座，截至 2026-10-01。」
- 「只在页面上显示和复制，不会自动发送。「只复制未开赛」只复制当前时间还没有开赛的场次。」

写提示之前先做一次判断。如果删掉这句话之后，读者仍然知道数据从哪里来，也仍然知道界面怎么操作，少掉的只是一条实现规则，这句话就属于内部规则，必须留在文档里。

## 前端 PR 自查

提交前端改动并请分析师审阅之前，作者先完成本节核对。本节标题里的 PR 是拉取请求（Pull Request）的简称。有一项对不上，就先改文案或把说明移回文档，再请分析师审阅。

- [ ] 本次改动里的页面正文、问号提示（`HelpTip`、`LabelWithHelp`、Tooltip）和列标题悬停提示（`headerTooltip`）没有程序逻辑，没有内部规则，也没有业务口径。
- [ ] 每一条提示都能归入「数据来源」或「如何使用」其中一类，并且是完整句子。不能归入这两类的句子已经改写，或已经移到文档里。
- [ ] 没有把缺数据时的回退、补数、跳过计算写进页面或提示。例如不得出现「盘口或抓取时刻缺失的格子不计算预警」这类内部处理说明。
- [ ] 列标题没有用括号夹注释。需要提示时只用 `headerTooltip`，内容仍然只说明数据来源或如何使用。

## 待确认星号

认不出的球队和赛事，在名称旁边显示同一个橙色星号，鼠标悬停时只显示「待确认」。页面上不写解释句。

- 球队：数据表读 `home_team_pending_confirm`、`away_team_pending_confirm`。赛程、当日消息预览和比赛详情读同名扁平字段，与 `teams_pending_confirm.home` / `.away` 同值。字段缺席时，来源名与规范名都空则标星，否则才使用队名兜底名单。接口给出布尔值时以接口为准。
- 赛事：数据表、赛程列表、当日消息预览和比赛详情标题都读 `league_pending_confirm`。字段缺席时，已升格的常用名不标星；临时名、还没有常用名的来源名，以及来源名与规范名都空时标星。规范名缺席时，`league_id` 为空与规范名为空等价。接口给出布尔值时以接口为准。
- 赛程、当日消息、比赛详情和数据表的赛事、主队、客队走同一套显示：优先取规范名，再映射成常用名。赛程读 `league_canonical`、`home_team_canonical`、`away_team_canonical`（嵌套的 `competition.canonical`、`teams.home_canonical`、`teams.away_canonical` 同值）。这些字段缺席时才用来源文本。格子里不显示原始别名。页面不另造名称。
- 赛事显示以雷速常用名为准。巴西甲级联赛的页面显示名是「巴西甲」，「巴甲」仅作别名。
- 复制出去的当日消息不含这颗星，星号只出现在页面预览里。

## 名称悬停

赛事名和队名悬停时列出别名。每条别名单独占一行，前面不加「其他名称」或「别名」。没有别名时，队名不显示悬停；赛事名仍显示来源名，不出现空悬停。星号的悬停仍只显示「待确认」。

## 各页面说明（v0.1.6 从页面上移到问号里的内容）

以下内容在 v0.1.6 之前直接写在页面上，随后被移入问号提示，并在这里留档。自规则二（2026-10-18）起，留档不等于现行提示文案：其中属于业务口径、程序逻辑或内部规则的句子只留在本文档和 `docs/schema/` 的口径文档里，不得再写入页面、问号提示或列标题悬停提示。问号和列标题悬停只保留数据来源或如何使用。

### 所有页面
- 页眉标题与浏览器标题为「比赛分析工具」。
- 每个页面底部有一条固定的免责声明：「本站基于公开网络数据做足球比赛分析与展示，仅供个人学习与研究，不构成任何投注建议。请理性看球；如需参与中国体育彩票竞彩，请前往官方线下门店。」版面不够时可以分成两行，意思不变。声明里的「投注」只出现在这句免责声明中。
- 已删除旧页脚说明「主清单默认竞彩 · 预测方向主/客/不下注 · 结算默认澳门收盘」。这些口径分别在赛程页、比赛详情页的问号里说明：主清单默认只看竞彩场；预测方向是主队、客队或无方向；没有写明结算盘时，平博临盘优先，没有再用澳门。已经冻结的预测仍显示该行自己的结算盘，旧方案可能仍是澳门临盘。接口里的方向取值「不下注」仍按原值识别，页面上写成「无方向」。

### 当日赛程
- 默认显示北京时间今天所属的竞彩日：北京时间 00:00 到 11:30 开赛的场次属于前一个竞彩日；有竞彩编号的场次以编号里的星期为准。
- 同一竞彩日内按竞彩编号升序排列；没有编号的比赛排在最后，再按开赛时间排列。默认只看竞彩场。
- 「开赛时间」是北京时间；分钟未知时只显示到小时。
- 「当日方向预览」只在页面上显示和复制，不会自动发送；「只复制未开赛」只复制当前时间还没有开赛的场次。没有给出方向的日期显示「这一天没有给出方向的场次。」
- 「显示预测方向」展开亚盘、欧盘、大小、竞彩、竞彩让球五列。方向来自当时正式方案的冻结预测，没有方向时显示「-」。
- 亚盘按雷速体育的规则显示：+ 表示方案倾向的一方让球，- 表示方案倾向的一方受让。份数后面带 * 表示冻结预测没有记录份数，份数是按方案规则推算的，复制出去的文本不带 *。
- 竞彩让球按竞彩官方的规则显示：+ 表示主队受让，- 表示主队让球。
- 详细格式见 `docs/schema/schedule-page-prediction-direction-columns.md`。

### 日期（赛程、数据表）

- 打开日历或切换月份时，按正在看的月份请求 `GET /matches/dates`。契约见 `docs/schema/v2_0-matches-dates-api.md`（后端 PR #16）。
- 有比赛指正式库里这一天至少有一条比赛记录，不要求赔率、预测或赛果。没有记录的当月日期文字较淡并带虚线，仍然可以点选，不禁用。
- 上月、下月露在格子里的日期继续用日期组件自带的灰色，和「无比赛」不是同一种样式。
- 赛程页跟着当前范围（竞彩、扩展、全部）查询。数据表页固定只查竞彩。
- 某个月还没有返回，或接口失败时，当月日期保持普通样式，不把失败画成整月没有比赛。

### 比赛详情
- 「盘口」卡片依次显示各公司的初盘、中盘、临盘。
- 「竞彩胜平负不完整」：只有主胜赔率（主胜影子数据），缺少平和负的赔率，不当作完整的竞彩胜平负使用；数据表页对应位置显示灰字「竞彩胜平负不完整」。
- 竞彩让球没有数据时显示「竞彩让球：-」：本地采集器未接通或尚未采集，决策时刻的让球线以数据表页的让球线和决策让球线为准。有数据时显示的是当前主表里的竞彩让球数据。
- 排名、交锋场次、近 6 场进失球、伤停、人气差值的数据来源（例如手工底座、截至时间）放在各自的问号里。
- 「人气差值」是支持率差值。库里存的是小数，页面只做显示换算：乘以 100，保留 1 位小数，不写百分号（例如 0.053 显示为 5.3）。数值由后端给出，页面不另算。没有数值时显示「-」。数据表只在「基本面」标签显示这一列。
- 「交锋近6」是主队视角的进球和失球。
- 赛前盘口和水位折线：展开后才请求变盘历史；默认公司为平博，可以切换。横轴公式是「x 等于负的系数乘以 log10（距开赛剩余分钟与 1 的较大值）」，调节系数只重新计算坐标，不重新请求接口；系数越大，曲线越向开赛端压缩。澳门叠加接口抓取的澳门数据，不叠加手工记录的澳门数据。
- 「预测结论」的方案方向仅供对照，不代表比赛结果。没有写明结算盘时，平博临盘优先，没有再用澳门。卡片里的结算盘口是这一行自己的记录；已经冻结的预测可能仍是澳门临盘，和没有写明时的默认口径不是一回事。方向标签把接口取值「不下注」显示为「无方向」。
- 「依据要点」列在「预测结论」卡片里。独立的网页「预测」页已在 v0.1.8 删除；旧网址 /predictions 会重定向到赛程页。


### 数据表
- 盘口、预测和赛果在一张表里看全；高亮规则已经预设，预测只读、已经冻结。
- 图例里各标记（「规」「API」「核」、灰字盘口、待归阶段、档位换算也上色、即时列开关、每条规则的备注、术语说明）的说明都放在图例里对应的问号中，完整口径见 `docs/schema/v2_0-data-table-highlight-rules.md`。
- 状态栏：右键点击一行可以复制本行或打开详情，双击一行打开详情；数据来源是批量接口。
- 列标题「收盘·参考」（原「收盘（时间未知）· 参考」）、「多家平均」（原「多家平均（参考）」）、只有主胜的欧赔分组（原标题带「（仅主胜）」）曾经把说明放进列标题悬停。按规则二，这些悬停只保留数据来源或如何使用；业务口径留在本文档和口径文档里。
- 「结算机构」只改变结算用的盘口和水位，预测方向不变。没有写明结算盘时，平博临盘优先，没有再用澳门。结果格只在接口标明回退时标出实际机构。已经冻结的预测仍读该行自己的结算盘，旧方案可能仍是澳门临盘，不要把默认口径当成这些行的结算盘。
- 日期范围的日历和赛程页同一套无比赛样式，但数据表固定只查竞彩。见上面「日期（赛程、数据表）」。

### 份数换算
- 导航名是「份数」，页标题是「份数换算」。只把份数换算成金额来展示，不修改已经入库的预测；多个方案对比时请分开计算，避免共用同一天的 10 份上限。金额下限在页面上写成「单笔」。
- 汇率表为空时金额按人民币展示，换算逻辑还没有接入。
- 「剩余资金」可以不填，不填时使用最新的资金快照或计算本金。

### 方案工场
- 可以列出方案、选模板生成新版本、做验证（复用缓存的结果或新建验证）；不影响现网默认方案 CFFXDJ_5_V3；这里生成的方案默认是影子状态，只用于工场试跑。
- 各模板的说明放在「从模板生成方案」标题的问号里。

### 验证
- 这一页还在建设中，等后端的方案定义和验证缓存表定下来以后接入。同一方案、同一验证形式、同一数据指纹的验证直接复用结果，不重新计算。

### 对比
- 多选方案后拉取对比数据；结算灵敏度用同一批记录按真实水位重新结算，作为副表，用不同颜色的曲线叠加显示。摘要里的场次计数写成「方向数」，冲突表写成「双边方向」。
- 后端返回的「公平对照」和「冲突处理」说明放在对应标签的问号里。
- 回落比例偏高时，真实水位副表只能作为同一批记录的灵敏度参考，不要当作主要的对比结论。
- 「查看已有验证记录」只读取已有的验证记录，不新建记录。
- 开始对比会新建验证记录。接口标明只读，或健康检查读不到元信息时，开始对比和自动验证不可用。meta.db 只有在响应里明确写出且不是 live 时才因此停止；正常 live 响应（含没有 meta.db 的响应）不因此锁定。页面只连接正式库。
- 对比请求不写结算盘，沿用接口缺省：平博临盘优先，没有再用澳门。结算标签显示接口返回的结算盘。这一口径用于本次对比，不会改写已经冻结的预测；比赛详情和数据表仍显示每一行自己的结算盘，旧方案可能仍是澳门临盘。
