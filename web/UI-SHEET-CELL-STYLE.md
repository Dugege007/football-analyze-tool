# 数据表单元格样式规范 v1.4

- **状态**：2026-10-21 缺测字面量统一为单个 ASCII `-`（v1.4）。
- **适用范围**：`web/` 数据表（sheet2）单元格的**书写格式、色字、空态、单元格填充**。列顺序与取数口径见 `docs/schema/` 与 ops 列清单，不在本文重复。
- **与 `web/UI-GUIDELINES.md` 的关系**：本文只管「格子里长什么样」。页面正文、问号、列标题悬停仍遵守 UI-GUIDELINES：不写业务口径、不写色字含义、不写空态判定规则。色与格式的解释只留在本文与代码注释。

---

## 0. 底层规则（两正交轴）

上色之前必须先选轴，禁止「看着顺眼」临时造色。

| 轴 | 语义 | 色 |
|---|---|---|
| **升降／多少（valence）** | 升高、多的、大的、高的等**正向** | **红** `.t-red` |
| 同上 | 降低、少的、小的、低的等**负向** | **绿** `.t-green` |
| **主客侧别（side）** | 和主队相关 | **橙** `.t-orange` |
| 同上 | 和客队相关 | **蓝** `.t-blue` |

选型顺序：是进失成对？→ 升降轴分段红／绿。否则是升降／多少／大小高低？→ 红／绿。否则是主／客属性或偏主／偏客？→ 橙／蓝。否则默认正文。

## 1. 色值与 CSS 类（唯一对照表）

实现必须使用下表中的 class；禁止在单元格里写内联色值，除非新增 token 并先改本表。

| 角色语义 | 色值 | CSS class（`web/src/sheet2/sheet2.css`） | 说明 |
|---|---|---|---|
| 升降轴·正向（升／多／大／高／进） | `#cf1322` | `.t-red` 或水位 `.mv-up` | 与水位上涨同色值 |
| 升降轴·负向（降／少／小／低／失） | `#389e0d` | `.t-green` 或水位 `.mv-down` | 与水位下跌同色值 |
| 侧别·主 | `#d46b08` | `.t-orange` | 主队相关；预测／赛果「主」 |
| 侧别·客 | `#1d39c4` | `.t-blue` | 客队相关；预测／赛果「客」 |
| 默认正文 | 继承表格默认（近黑） | （不加色类） | 零值、平／走水、分隔符、无侧别数字 |
| 次要／估算标记 | `#999` | `.t-gray` | 仅 xG 估算／推导等已有标记 |
| 警示加重 | `#d4a106` | `.t-yellow` | 既有用途；新列默认不用 |

## 2. 角色分类

每一格（或格内每一段数字）必须且只能归入下列角色之一。

### 2.1 升降／多少（valence）

| 取值 | 色 |
|---|---|
| 升、多、大、高、进（gf） | `.t-red` |
| 降、少、小、低、失（ga） | `.t-green` |
| 无升降／多少语义 | 默认正文，或改走侧别轴 |

大小球方向短文案「大」「小」按本轴：大红、小绿（改码时须把现网 `bookCellTone` 的大橙小蓝迁到本轴，并改相关单测）。

### 2.2 主客侧别（side）

| 取值 | 色 |
|---|---|
| home／主 | `.t-orange` |
| away／客 | `.t-blue` |
| draw／平／走水／无方向 | 默认正文 |

**列头**默认不染色。侧别色只加在单元格数值或方向短文案上。

偏主／偏客的有符号差值（人气差值：主减客）也归本轴：正橙、负蓝、零默认。整格一个色类；负号与数字同色。

### 2.3 进失对（quantity pair：gf／ga）

一格内同时展示进球类与失球类数量（近况进失、交锋近6 等）。归**升降轴**，必须分段着色：

| 段 | 色 |
|---|---|
| 进（gf） | `.t-red` |
| 分隔符 `/` | 默认正文 |
| 失（ga） | `.t-green` |

```html
<span class="t-red">10</span>/<span class="t-green">8</span>
```

禁止整格只加一个色类。不因列名带「主」或「客」而整格涂橙／蓝。

### 2.4 角色互斥与优先级

1. 先分轴：有「升／降／多／少／大／小／高／低／进／失」语义 → 升降轴；有「主／客／偏主／偏客」属性且无升降多少语义 → 侧别轴。
2. 进失对优先：数字按进红／失绿，不按列名侧别整格上色。
3. 人气差值是偏主／偏客 → 侧别轴橙／蓝，不用红／绿。
4. 同一色值多场景（绿＝失／跌／小；红＝进／升／大）用分段 DOM 或升降箭头区分；不要把含义写进页面。

### 2.5 新列选型流程

1. 写出该列展示的是什么（只进文档／PR 说明，不进页面）。
2. 按 §0 选型顺序选轴与色。
3. 选定空态类型（§4）。
4. 选定书写格式（§3）。
5. 若需要新色，先改 §1 再改代码。

## 3. 书写格式

### 3.1 冒号与斜杠

| 用途 | 分隔符 | 示例 | 说明 |
|---|---|---|---|
| 官方比分、赛果比分列 | `:`（是否空格随既有比分列） | `2:1` | **仅**真实比分 |
| 统计类进／失（近况、交锋近6 等） | `/`，两侧无空格 | `10/8`、`3/0` | **禁止**写成 `10:8` 或 `10 : 8` |

交锋近6 与近10／近6 主客进失一律 `进/失`。两端都是有限数字才输出该串；任一端缺失则整格走空态，不输出半截。

### 3.2 人气差值

- 库内仍存小数（例如 `0.053`）。
- 页面：乘以 100 后保留一位小数，**不写百分号**。例：`5.3`、`-13.5`、`0.0`。
- `-0.0` 显示为 `0.0`，并按侧别零处理（默认正文）。

### 3.3 排名

有限整数原样显示（`5`、`12`）。不补零、不写「名」。

### 3.4 xG

有限数字固定两位小数（既有 `toFixed(2)`）。估算／推导可用 `.t-gray` 与既有悬停短词；不在格子写口径长句。

### 3.5 其它数字

盘口、水位、期望等保持既有 formatter；本规范不改其小数位，只约束其轴上色（若该列已归入 §2）。

## 4. 无数据填写规则（空态，全表统一）

本节是数据表**唯一**空态口径。每一格至多命中一类；四类互斥、含义不重叠。新列必须先归类再写渲染。

### 4.1 四类定义（互斥）

按「我们知道什么」划分，不按字段长什么样划分：

| 类型 | 含义（只此一义） | 格子只显示 | 何时成立 |
|---|---|---|---|
| **缺测** | 该指标在本场／本队**尚未测到或库里没有**，不知道有没有、也不知道数值 | `-`（U+002D，单个） | 无有效观测：null／缺字段／空串；进失对缺任一端；无 status 壳时的「没数据」 |
| **确认空** | **已经查过**，业务上确认「就是没有这项内容」（不是「还没采到」） | 该列固定短词；伤停目前为 `无` | 且仅当接口给出「已知为空」标志（伤停：`obs.injury.known_empty === true`）。无此标志不得用本类 |
| **未就绪** | 指标走 status 壳，流程上**还没轮到填**（待开盘、待计算等） | `-`（U+002D）或壳约定的 `未填写` | 壳 `status` 为 `not_filled` 或 `pending`。`not_filled` → `-`；`pending` → `未填写`。二者都表示「流程未到」，不是「库里丢了」 |
| **不可得** | 已尝试或已判定，**拿不到可用值**（源不足、源失败、不足以计算） | `无法获取` | 壳 `status` 为 `unavailable` 或 `insufficient` |

**互斥要点（禁止混用）：**

- 「缺测」≠「确认空」：前者是未知，后者是已知没有。
- 「缺测」≠「未就绪」：前者无壳／无流程态；后者有壳且状态是还没填。
- 「未就绪」≠「不可得」：前者以后可能有数；后者本格按当前规则给不出数。
- 「确认空」≠「不可得」：前者有内容但是空集；后者是值算不出来。
- 有效零值（`0`／`0.0`）不是空态，按 §2／§3 正常显示。

### 4.2 判定顺序（命中即停）

1. 有 status 壳 → 只看 `status`：`pending`／`not_filled` → **未就绪**；`unavailable`／`insufficient` → **不可得**；有有效 `value` → 走出空态，渲染数值。
2. 无壳，但有「已知为空」标志 → **确认空**。
3. 其余无效／缺失 → **缺测**。
4. 不得用空数组、空对象、假值冒充「确认空」；不得把无壳的 null 写成「无法获取」或「未填写」。

### 4.3 显示与实现硬约束

- 一格只出现上表一种字面量；禁止 `- -` 与两行叠空态。缺测和未就绪的 `not_filled` 都显示单个 `-`，靠有没有 status 壳区分。
- 进失对：两端皆有限数字才输出 `进/失`；缺一端整格 **缺测**。
- 空态格子**不着色**。
- 页面／Tooltip 不解释空态含义（见 UI-GUIDELINES）。

### 4.4 基本面（#65）列 → 空态

| 列 | 类型 |
|---|---|
| 近10／近6 主客进失、交锋场次、交锋近6、主排名、客排名、人气差值、天气 | 缺测 → `-` |
| 伤停 | 确认空 → `无`，否则缺测 → `-` |
| xG 六列 | 未就绪 → `-`；不可得 → `无法获取` |

### 4.5 新列空态选型

1. 是否「查过且确认没有」且有接口标志？→ **确认空**（定短词并写入本表）。
2. 是否 status 壳？→ 只用 **未就绪**／**不可得**（字面量固定）。
3. 否则 → **缺测**（单个 `-`）。
4. 映射写入 §4.4 与 §6 后再改代码。

## 5. 单元格填充（背景）

色字与背景分开。本规范不要求基本面列使用背景填充。

既有填充（保持原规则，新基本面列默认不用）：

| 用途 | class 示例 |
|---|---|
| 水位／预警档 | `.al-light`／`.al-medium`／`.al-high` |
| 预测结算对错 | `.f-win`／`.f-winhalf`／`.f-losehalf`／`.f-lose` |
| 竞彩日星期底色 | `.wd-1` … `.wd-7` |

新列若需要背景，必须先归类到上表某一用途或修订本规范新增用途；禁止用背景代替 §2 色字。

## 7. 实现约束（改码时遵守）

1. 色类只使用 §1 所列；挂在 `.sheet2` 下既有 class。
2. 进失对必须分段 DOM／片段着色，不能 `className` 打在整串 `"10/8"` 上；进用 `.t-red`，失用 `.t-green`。
3. 人气显示与详情页若并存，宽表与详情须同一格式（无 `%`、同一侧别色）；改显示时同步改 `UI-GUIDELINES.md` 里过时的「带百分号」表述。
4. 交锋近6 与详情页须同一斜杠格式；单测须断言 `10/8`，不得再锁 `10 : 8`。
5. 大小球「大」「小」须从侧别橙／蓝迁到升降红／绿，并更新 `bookCellTone` 相关单测。
6. 空态只许 §4 字面量；单测须覆盖缺测为单个 `-`、禁止 `- -`，并覆盖伤停「确认空／缺测」分支。
7. 格子、问号、`headerTooltip` 不写色字或空态含义说明（UI-GUIDELINES 规则一／二）。
8. 数据缺失（例如近窗排名全空）显示 `-` 即为正确；补数属数据任务，不在样式 PR 里伪造数字。
